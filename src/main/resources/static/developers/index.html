Snake is a desktop game (Java Swing) backed by a deployed Spring Boot service. Both the desktop app and this website consume the same REST API to display online leaderboards.

Engineering highlights

The service combines validated REST endpoints, PostgreSQL persistence, session-protected score submission, and a shared contract for the desktop and web clients.

🏗️

Layered service design

Controllers delegate business rules and database work to focused services, with DTO-based responses for predictable API output.

Mode-aware queries keep ranking behavior consistent across clients.

🔐

Secure submissions

Score submission requires a short-lived session token and a validated request body.

Reduces abuse without forcing account creation.

⚡

Ranked queries

Paginated leaderboard reads support map, mode, and difficulty filters.

Same endpoint serves both desktop and web.

Tech stack

Core technologies used across the stack.

Backend

  • Java 21 + Spring Boot 4
  • PostgreSQL + Flyway migrations
  • Spring JdbcClient + response DTOs
  • Session tokens + rate-limited score writes

Desktop client

  • Java Swing UI
  • Multiple modes, maps, and difficulty levels
  • A* AI, replay, and persistence systems
  • Shared online leaderboard API client

Web frontend

  • Static HTML/CSS/JS served by Spring Boot
  • Responsive layout + glass UI
  • Live leaderboard filters and pagination

Deployment

  • GitHub Actions CI and deployment workflow
  • Koyeb-hosted service with health monitoring
  • Single-origin hosting for the website and API

API reference

Endpoints consumed by the desktop client and the web UI.

GET /api/leaderboard

Fetch leaderboard entries filtered by mapId, mode, and optional difficulty.

Query
mapId, mode, difficulty (optional), limit, offset 
GET /api/leaderboard?mapId=0&mode=STANDARD&limit=25&offset=0
Web behavior
The website filter logic matches the desktop client (mode controls map behavior; “ANY” difficulty is not sent).
POST /api/session

Start a short-lived session used to authenticate score submissions. 

POST /api/session
Headers for submit
Use X-Session-Id and X-Session-Token returned by this endpoint.
POST /api/scores

Submit a score. Requires session headers and validated JSON request body. 

POST /api/scores
X-Session-Id: <uuid>
X-Session-Token: <token>
Validation
Player name pattern + bounds checks keep data clean and reduce abuse.
GET /health

Health check endpoint for uptime monitoring and deploy verification.
